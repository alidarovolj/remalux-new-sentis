# 🔍 ГЛУБОКИЙ АУДИТ СИСТЕМЫ ГЕНЕРАЦИИ ПЛОСКОСТЕЙ

## Исполнительное резюме

Проведен комплексный аудит системы генерации плоскостей в Unity AR-проекте `remalux-new-sentis`. Выявлено 7 критических проблем, блокирующих корректную работу генерации плоскостей из сегментационных масок, а также фундаментальные архитектурные ограничения.

**Основная проблема:** Система страдает от каскадного отказа аппроксимаций - каждый этап конвейера (поиск областей → позиционирование → расчёт размеров) вносит существенную погрешность, приводящую к неточному позиционированию и негабаритным плоскостям.

**Двухуровневое решение:**
1. **Краткосрочные исправления** - устранение 7 критических проблем для быстрого улучшения
2. **Долгосрочная архитектурная переработка** - математически обоснованная замена эвристик на точные алгоритмы

## 🎯 АРХИТЕКТУРА СИСТЕМЫ

Система генерации плоскостей состоит из следующих компонентов:

```
WallSegmentation → OnSegmentationMaskUpdated → ARManagerInitializer2 → Physics.Raycast → Plane Creation
     ↓                        ↓                         ↓                    ↓              ↓
  ML-модель            RenderTexture             Анализ областей        Поиск стен      GameObject
   Sentis              256x256/512x512            FindWallAreas()      рейкастинг      + MeshRenderer
```

## 🏗️ ФУНДАМЕНТАЛЬНЫЕ АРХИТЕКТУРНЫЕ ПРОБЛЕМЫ

Система генерации плоскостей в текущем виде представляет собой цепочку эвристических методов, каждый из которых вносит существенную погрешность:

| Этап | Текущий метод | Проблема | Предлагаемое решение |
|------|---------------|----------|----------------------|
| **Анализ формы** | `FindWallAreas()` - поиск "клякс" | Даёт неточную границу | **Поиск контуров** с алгоритмом Сузуки |
| **Позиционирование** | Одиночный рейкаст из центра масс | Чувствителен к шуму | **PCA-регрессия** по облаку точек |

| **Передача данных** | Синхронное чтение с GPU | Блокирует основной поток | **AsyncGPUReadback** |

## 📋 КРАТКОСРОЧНЫЕ ИСПРАВЛЕНИЯ (БЫСТРЫЕ ПОБЕДЫ)

### 🚨 Проблема 1: Флаг useDetectedPlanes блокирует сегментацию

**Статус:** ✅ РЕШЕНА В КОДЕ

**Описание:** 
В ARManagerInitializer2 предусмотрен флаг `useDetectedPlanes`, который при значении `true` переключает систему на использование встроенного обнаружения плоскостей AR вместо генерации из сегментационной маски.

**Анализ кода:**
```csharp
// Строка 248: Принудительная установка
useDetectedPlanes = false;

// Строки 252-256: Правильная логика подписки
if (!useDetectedPlanes) {
    SubscribeToWallSegmentation();
}

// Строки 324-329: Правильная логика в Update
if (useDetectedPlanes) {
    Debug.LogWarning("useDetectedPlanes=true, пропускаем обработку сегментации");
} else if (maskUpdated) {
    ProcessSegmentationMask();
}
```

**Решение:** ✅ УЖЕ РЕАЛИЗОВАНО
Код правильно устанавливает `useDetectedPlanes = false` и корректно обрабатывает логику сегментации.

### 🚨 Проблема 2: Маска слоёв рейкаста не охватывает SimulatedEnvironment

**Статус:** ⚠️ ЧАСТИЧНО РЕШЕНА

**Описание:**
Для поиска поверхностей стен система выполняет `Physics.Raycast` с маской слоёв `hitLayerMask`. Настройки могут не включать все необходимые слои.

**Текущие настройки:**
```csharp
// Строка 62: Настройка в инспекторе
[SerializeField] private LayerMask hitLayerMask = (1 << 0) | (1 << 8) | (1 << 30) | (1 << 31);
// Default + SimulatedEnvironment + XR Simulation + Layer31 (LivingRoom)

// Строка 1250: Альтернативная маска в CreatePlaneForWallArea
LayerMask raycastLayerMask = LayerMask.GetMask("SimulatedEnvironment", "Default", "Wall");
```

**Проблемы:**
1. Разные методы используют разные маски слоёв
2. Возможно несоответствие номеров слоёв их названиям

**Решение:**
```csharp
// 1. Унифицировать использование hitLayerMask везде
// В методе CreatePlaneForWallArea заменить:
LayerMask raycastLayerMask = this.hitLayerMask;

// 2. Проверить настройки слоёв в проекте:
// SimulatedEnvironment = Layer 8
// Default = Layer 0  
// Wall = Layer 30 (если используется)
// XR Simulation = Layer 31

// 3. Добавить проверку слоёв при старте:
private void ValidateLayerMask() {
    string[] layerNames = {"Default", "SimulatedEnvironment", "Wall"};
    foreach(string layerName in layerNames) {
        int layer = LayerMask.NameToLayer(layerName);
        if (layer == -1) {
            Debug.LogWarning($"Слой '{layerName}' не найден в проекте!");
        }
    }
}
```

### 🚨 Проблема 5: Неправильное преобразование координат сегментации

**Статус:** ⚠️ ТРЕБУЕТ ИСПРАВЛЕНИЯ

**Описание:**
Преобразование координат пикселей маски в мировые координаты содержит потенциальные ошибки в:
1. Системе координат UV (Y-инверсия)
2. Расчёте мировых размеров плоскости
3. Позиционировании относительно камеры

**Проблемные места:**

```csharp

// Строки 1128-1152: Расчёт центра массы
return new Vector2(
    (centerX / totalMass) / textureWidth,    // X правильно
    (centerY / totalMass) / textureHeight    // Y может требовать инверсии
);
```

**Решение:**
```csharp
// 1. Исправить преобразование Y-координаты

    // ... existing code ...

            1.0f - (centerY / totalMass) / textureHeight  // ❗ ИНВЕРСИЯ Y
        );
        return centerOfMass;
    }
    // ...
}

// 2. Проверить корректность ViewportPointToRay
// UV координаты: (0,0) = нижний левый, (1,1) = верхний правый
// Если маска читается сверху-вниз, нужна инверсия Y

// 3. Добавить валидацию расчётов
private void ValidateCoordinateTransform(Vector2 uvCoords, Vector3 worldPos) {
    if (enableDetailedRaycastLogging) {
        Debug.Log($"UV: {uvCoords} → World: {worldPos} → Distance: {Vector3.Distance(worldPos, mainCamera.transform.position)}");
    }
```

### 🚨 Проблема 6: Слишком жёсткие фильтры по размеру областей

**Статус:** ⚠️ ТРЕБУЕТ НАСТРОЙКИ

**Описание:**
Система фильтрует области сегментации по нескольким критериям, которые могут быть слишком строгими:

```csharp
// Текущие значения:
minPixelsDimensionForArea = 1     // Минимальная ширина/высота (очень низко)
minAreaSizeInPixels = 150         // Минимальная площадь (было 1500)
wallPixelThreshold = 120          // Порог красного канала (высоко)
```

**Анализ фильтрации:**
```csharp
// Строки 971-983: Основной фильтр
if (area.width >= minPixelsDimensionForArea && 
    area.height >= minPixelsDimensionForArea && 
    area.width * area.height >= minAreaSizeInPixels) {
    // Область принимается
} else {
    Debug.Log("FILTERED Area - слишком мала");
}

// Строки 1060-1098: Дополнительная валидация
float minWallRatio = 0.5f; // 50% пикселей должны быть стеной
bool isValid = (float)wallPixels / totalPixels >= minWallRatio;
```

**Проблемы:**
1. `wallPixelThreshold = 120` может быть слишком высоким
2. `minWallRatio = 0.5f` строгий для зашумлённых масок
3. Отсутствует адаптивная настройка порогов

**Решение:**
```csharp

[Header("📐 Адаптивная фильтрация")]
[SerializeField, Range(50, 200)] private byte adaptiveWallThreshold = 120;
[SerializeField, Range(0.2f, 0.8f)] private float minWallRatio = 0.4f;  // Снижено
[SerializeField, Range(50, 500)] private int adaptiveMinAreaSize = 150;

// 2. Добавить адаптивную логику
private void AdaptFilterThresholds() {
    // Если в нескольких кадрах подряд нет областей - снижаем пороги
    if (consecutiveEmptyFrames > 5) {
        adaptiveWallThreshold = Math.Max(50, adaptiveWallThreshold - 10);
        adaptiveMinAreaSize = Math.Max(50, adaptiveMinAreaSize - 25);
        Debug.Log($"Адаптивно снижены пороги: threshold={adaptiveWallThreshold}, minArea={adaptiveMinAreaSize}");
    }
}

// 3. Добавить статистику фильтрации
private void LogFilteringStats(List<Rect> allAreas, List<Rect> acceptedAreas) {
    float acceptanceRate = (float)acceptedAreas.Count / allAreas.Count;
    if (acceptanceRate < 0.3f) {
        Debug.LogWarning($"Низкий процент принятых областей: {acceptanceRate:P}. Возможно, слишком строгие фильтры.");
    }
}
```

### 🚨 Проблема 7: XR Simulation не предоставляет текстуру камеры

**Статус:** 🔴 КРИТИЧЕСКАЯ - ТРЕБУЕТ РЕШЕНИЯ

**Описание:**
В режиме XR Simulation `ARCameraManager.TryAcquireLatestCpuImage()` всегда возвращает `false`, так как симулированное окружение не генерирует реальных CPU-изображений камеры.

**Цепочка проблемы:**
```
XR Simulation → ARCameraManager.TryAcquireLatestCpuImage() = false → 
WallSegmentation.GetCameraTexture() = null → PerformSegmentation() не выполняется →
OnSegmentationMaskUpdated не вызывается
```

**Текущий workaround:**
```csharp
// В WallSegmentation есть флаг forceWebcamUsage
[SerializeField] private bool forceWebcamUsage = false;
```

**Комплексное решение:**

1. **Вариант A: Render Texture от камеры симуляции**
```csharp
// Новый класс: XRSimulationCameraFeed
public class XRSimulationCameraFeed : MonoBehaviour {
    [SerializeField] private Camera simulationCamera;
    [SerializeField] private RenderTexture cameraFeedTexture;
    
    private void Start() {
        // Создаём RenderTexture для камеры симуляции
        cameraFeedTexture = new RenderTexture(640, 480, 16);
        simulationCamera.targetTexture = cameraFeedTexture;
    }
    
    public Texture2D GetCurrentFrame() {
        // Конвертируем RenderTexture в Texture2D
        RenderTexture.active = cameraFeedTexture;
        Texture2D frame = new Texture2D(cameraFeedTexture.width, cameraFeedTexture.height);
        frame.ReadPixels(new Rect(0, 0, cameraFeedTexture.width, cameraFeedTexture.height), 0, 0);
        frame.Apply();
        RenderTexture.active = null;
        return frame;
    }
}
```

2. **Вариант B: Модификация WallSegmentation**

# 🚨 КРИТИЧЕСКОЕ ИСПРАВЛЕНИЕ - ПЕРЕПОЛНЕНИЕ ПАМЯТИ В СИСТЕМЕ КОНТУРОВ

## 📋 Проблема
В результате тестирования системы выявлена критическая ошибка `OutOfMemoryException` в алгоритме поиска контуров Сузуки-Абэ:

```
OutOfMemoryException: Out of memory
ARManagerInitializer2.TraceContour (...) (at Assets/Scripts/ARManagerInitializer2.cs:2353)
ARManagerInitializer2.FindContours (...) (at Assets/Scripts/ARManagerInitializer2.cs:2298)
```

### 🔍 Диагностика
- **Симптомы**: Алгоритм TraceContour попадает в бесконечный цикл или создает огромное количество точек контура
- **Причина**: Отсутствие защиты от переполнения памяти и зацикливания в алгоритме трассировки контуров
- **Контекст**: Маски сегментации приходят корректно (56x56, ~90% красных пикселей), но система контуров не может их обработать

## 🛡️ Реализованное решение

### 1. **Защита от переполнения памяти**
```csharp
// Новые настройки в инспекторе
[Tooltip("Максимальное количество точек в одном контуре")]
[SerializeField, Range(500, 10000)] private int maxContourPoints = 5000;
[Tooltip("Максимальное количество итераций трассировки контура")]
[SerializeField, Range(1000, 20000)] private int maxContourIterations = 10000;
```

### 2. **Многоуровневая защита в TraceContour**
```csharp
// Используем настройки из инспектора
int MAX_CONTOUR_POINTS = maxContourPoints;
int MAX_ITERATIONS = maxContourIterations;
var visitedStates = new HashSet<(int, int, int)>(); // Обнаружение циклов

// Проверка на превышение лимита точек
if (contour.points.Count >= MAX_CONTOUR_POINTS)
{
    Debug.LogWarning("Достигнут лимит точек контура. Прерывание трассировки.");
    break;
}

// Проверка на превышение лимита итераций
if (++iterations >= MAX_ITERATIONS)
{
    Debug.LogWarning("Достигнут лимит итераций. Возможно зацикливание.");
    break;
}

// Проверка на зацикливание состояния
var currentState = (x, y, dir);
if (visitedStates.Contains(currentState))
{
    Debug.LogWarning("Обнаружено зацикливание в позиции");
    break;
}
```

### 3. **Fallback система**
```csharp
// Автоматический fallback к старой системе областей при ошибке
if (useContourBasedDetection)
{
    try
    {
        List<Contour> contours = FindContours(textureData, ...);
        // Обработка контуров
    }
    catch (System.Exception ex)
    {
        Debug.LogError($"Ошибка в системе контуров: {ex.Message}");
        useContourBasedDetection = false; // Переключаемся на старую систему
    }
}
```
